## Рекомендации

### Для использования

1. **Для всех задач используйте базовый алгоритм** - он быстрее и точнее
2. Для графов >10K вершин базовый алгоритм всё ещё эффективен
3. Используйте `--no-viz` для больших графов для ускорения генерации отчётов

### Для разработки

1. **КРИТИЧНО:** Базовый алгоритм возвращает NaN для графов с определёнными конфигурациями фиксированных вершин
2. Эвристический алгоритм требует оптимизации для практического использования
3. Рассмотрите возможность параллелизации для графов >100K вершин
4. Добавьте прогресс-индикатор для долгих операций
5. Добавьте валидацию результата перед возвратом (проверка на NaN/Infinity)

## Найденные проблемы

### 1. NaN в метриках базового алгоритма (КРИТИЧНО)

**Описание:** Для некоторых конфигураций фиксированных вершин базовый алгоритм возвращает NaN в метриках.

**Воспроизведение:**
```bash
./dotnet run --project src/QuadraticPlacement.CLI/QuadraticPlacement.CLI.csproj -- \
  report --input test_data/triangle_2fixed.txt --output report.html --no-viz
```

**Результат:**
```
Базовый алгоритм завершён за 0.01 сек
Суммарная длина: NaN
```

**Файл:** `test_data/triangle_2fixed.txt`
```
3 3 2
1 2
2 3
3 1
1 0.0 0.0
2 100.0 0.0
```

**Возможная причина:** Сингулярная или плохо обусловленная матрица Лапласа для данной конфигурации фиксированных вершин.

**Влияние:**
- Команда `solve` не может сохранить JSON (ошибка сериализации NaN)
- Команда `report` работает, но показывает NaN в метриках

**Рабочее окружение:** Эвристический алгоритм работает корректно для тех же данных.

### 2. Ошибка сериализации NaN в JSON

**Описание:** При попытке сохранить результат с NaN метриками в JSON возникает ошибка.

**Сообщение об ошибке:**
```
.NET number values such as positive and negative infinity cannot be written as valid JSON.
```

**Рекомендация:** Добавить валидацию метрик перед сериализацией или использовать `JsonNumberHandling.AllowNamedFloatingPointLiterals`.
